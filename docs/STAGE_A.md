## 3. 修改内容与设计理由

### 3.1 纯规则核心（`js/rules_core.js`）
- **为什么**：规格要求目标、耐久、胜负不能依赖动画回调；编辑器试玩、正式游戏、批测必须同一套规则。
- 无 DOM / 计时器 / 动画回调 / `Math.random`（测试会扫描源码确认）。`apply(state, action)` 先校验，非法动作直接返回 `{ok:false, reason}`，**不扣步、不扣道具、不改任何状态**。
- 合法动作在接受时同步结算到稳定，输出事件日志：`swap / hammer / toolSwap / shuffle / wave / fall / end / guard`。游戏只负责把事件“演出来”。
- 每个结算波：快照 → 闭包（普通匹配、特殊连锁按延迟+ID 排序各触发一次）→ 收集障碍命中 → **一次性提交**。
  - 同一障碍实例（稳定 ID）一波最多 −1；重叠覆盖次数记在事件 `dedup` 里（用于解释“为什么只扣了一层”）；下一波可再次受伤。
  - 邻接伤害只来自普通匹配格；特殊攻击/锤子只伤害被覆盖的格（直接攻击）。
  - 糖霜：所在格参与匹配或被直接攻击时 −1 层，最后一层消失才计 1 格目标。
  - 箱子：固定占格，不可交换/匹配/掉落；阻挡重力；直线攻击穿过不截断；HP 归零才计目标。
- 重力：静态竖直段；段内被箱子分成子区，各自下落；**只有段顶有出生口的最上层子区才补子**（箱子下方不会凭空补子）。
- 第 5.5 节顺序：交换 → 逐波结算到稳定 → 先判胜（剩余步数 ×60 奖励）→ 再判步数用尽 → 无合法操作时免费洗牌（只动普通果冻，有上限）→ 失败则 `stuck` + 诊断。最后一步的连锁完成后先判胜。
- 随机：mulberry32，`fill / refill / shuffle` 三条独立流，各由 `hash(seed|名称)` 播种；视觉随机（粒子等）仍用 `Math.random`，**不接触玩法流**。开局最多 100 次、洗牌最多 200 次、单回合最多 60 波。
- 道具预览 = 结果：洗牌预览用随机流副本计算，确认时带 `expect` 哈希，不一致则拒绝（`stale_preview`）。
- 回放：`replay(def, seed, actions)` → `stateHash / eventsHash`；同规则版本 + 同内容 + 同 seed + 同输入 → 同哈希。

**与 v2 的行为差异（已明确选择，需留意手感）**
- 保留 v2 条纹方向（垂直于连线方向）。
- 生成特殊的锚点果冻按“普通收集”计 1 次，新特殊获得新 ID；特殊棋子被消除不计收集。
- 彩虹 + 特殊：两颗源都被组合消耗，不再各自单独触发（v2 会再触发一次另一颗）。
- 组合转换方向改为确定性（v2 随机）；同色选择平局按固定类型顺序。
- 洗牌只移动普通果冻（v2 连特殊一起洗）。
- 小锤可以敲箱子和只有糖霜的格。
- 得分：每次障碍命中 +20。

### 3.2 游戏表现层（`js/game.js` 重构）
- 删除写死的 LEVELS；`startDef(def, seed, source)` 用关卡定义 + seed 建立核心局，`buildVisuals` 从核心状态生成表现。
- `playFrom / playWave / playFall / playShuffle` 按事件顺序演出；每个回调都检查 `ep === G.epoch`，**重开后旧回调不能改新棋盘**。
- 障碍画在棋盘层（WebGL 果冻之下）：受击挤压、糖霜剥落、箱子归零后整只弹出下落（在特效层）；只在动画期间逐帧重绘棋盘层，其余时间按签名缓存。
- 空洞格不画格子；段内部出生口画小标记；HUD/结算支持最多 3 个目标与障碍图标；`stuck` 面板显示诊断。
- 预放特殊棋子的关卡（`editorNotes.ruleTestFixture`）标题下显示“规则测试关 · 非正式内容”。
- 进度：仅正式目录关卡通关时写 `jelly_m3_progress_v1`（按稳定 levelId，最佳剩余步数附带 contentRevision）；试玩和载入的文件不写。
- 动作拒绝提示（无道具、无可敲对象、箱子不能换位……）。
- JellyDebug 新增 `core / visualCheck / startLevelId / restart / loadLevelJSON / lastEvents / crates / hammer / moves / epoch`（仅自动化测试使用）。

### 3.3 关卡数据（`js/level_schema.js`，`levels/`）
- 字段：`schemaVersion, levelId, contentRevision, rulesetVersion, displayName, chapterId, board{rows, cols, playableMask, gravity:'down', spawners, exits:[]}, initial{fillMode, allowInitialMatches, placements[layer,row,col,typeId,special,hp,layers]}, spawnPool[typeId,weight], moveLimit, goals[], tools, scoring.stars, themeId, editorNotes`。运行时状态与关卡定义完全分离。
- 分层：terrain（可玩格/出生口）· underlay（糖霜）· occupant（果冻、箱子）· overlay（软糖绑带，阶段 B，仅保留结构，校验拒绝）。
- 规范化导出：固定键序，未知键保留并排序，摆放按层/行/列排序 → 导出再导入字节一致。高于当前的 schemaVersion 拒绝，不丢字段假装成功；迁移入口 `MIGRATIONS` 已留好。
- 校验三级：**A 结构错误**（阻止运行，43 类，如越界、void 摆放、重复占格、箱子压糖霜、HP/层数/权重越界、每个静态段必须且只能有一个段顶出生口、固定开局与“无三连且有合法操作”冲突……）、**B 可证明矛盾**（阻止发布：箱子/糖霜数量不够、收集类型不在补子池且开局不足……）、**C 设计警告**（被箱子切断无补给的区域、开局选择少、部分 seed 初始化失败……）；另跑 20 个 seed 的初始化模拟。结果绑定 contentHash + 规则版本，界面明确写“结构通过≠已证明可解”。

### 3.4 编辑器（`editor.html` + `js/editor.js`）
- 关卡列表（按章、搜索、验证状态徽标）、新建、复制（新 levelId，修订从 r1 起）、重命名（仅草稿；内置关卡保留 ID）、删除草稿。
- 资源栏按 `REGISTRY` 生成（不另维护障碍清单）：地形/设施（可玩格、空洞、出生口）、地面层（糖霜 1/2 层）、占据层（6 种果冻、箱子 1/2/3 HP、特殊棋子＝标注“规则测试夹具*”）、覆盖层（阶段 B 灰掉）。擦除只影响当前层。
- 笔刷 / 矩形 / 选择；一次拖动 = 一步撤销；删除可玩格时同一事务移除该格对象与出生口并自动重算出生口；非法组合在摆放时就提示原因（如“糖霜上不能放饼干箱”）。
- 设置：名称、章节、步数、星级分、道具数、目标（1–3 个：收集/清糖霜/开箱子，范围“全部”或“指定数量”）、补子池类型与权重、设计意图。
- 撤销/重做、手动保存 + 800 ms 自动保存；修改后旧校验结果失效；内容变化相对载入版本自动 contentRevision+1（同 levelId）。
- 校验面板：A/B/C 分色，点击定位到格（棋盘描边）或字段（输入框红框）。
- 导入（先解析校验，失败不破坏当前草稿）/ 导出真实 `levelId.json` 文件。
- 试玩：结构错误时拒绝；进入时保存草稿快照，把序列化文本发给 iframe 中的**正式游戏**（同一核心 + 正式表现）；侧栏显示 seed（可复制）、同 seed 重试、新 seed、实时步数/目标/道具/核心哈希、最近一条伤害/目标事件与事件记录；返回时核对草稿与快照字节一致。用 token 忽略旧实例的消息。

- **同版本 + 同 seed + 同输入 → 同 stateHash 与 eventsHash**（含“导出再导入的数据”重放），换 seed 结果不同。

- 直线攻击穿过箱子不截断；箱子阻挡下落；箱子下方不补子。
- 2 层糖霜第一次受击不减目标，第二次才减；锚点果冻在糖霜上且邻接箱子：只计 1 次收集、糖霜 −1、箱子 −1；新特殊不会在生成它的那一波自触发。
- 模糊测试：9 关 × 12 seed × 20 回合共 1650 回合、9572 次补子检查，逐波断言“每障碍每波最多 −1”“同一棋子不被消除两次”“清除目标进度 = 实际消失的实例数”“补子只来自有出生口的段顶且不在箱子下方”，全部成立（期间共去重 19 次重叠命中）。
- 无效动作（越界、不相邻、不成三、换箱子、空洞格、道具为 0、过期洗牌预览、未知动作、已结束的局）共 13 种 → 状态哈希、步数、道具、日志全部不变。
- 洗牌预览哈希 = 实际结果；箱子/糖霜不被洗牌移动；开局 100 次、洗牌 200 次上限到达后给出诊断且不扣道具。
- verify_05：seed 1–20 全部在最后一步判胜（剩 0 步不抢先判负）；另外 50 个 seed 也全部通过。

## 6. 尚未验证项与已知问题
- **未做真机/真人验证**：手感、可读性、性能都只在无头软件渲染下检查；障碍受击/弹出动效的手感未经人工试玩确认。
- **占位美术**：糖霜与箱子为程序化占位图，需正式美术替换（manifest 已标注）。
- 与 v2 的若干行为差异（第 3.1 节）会改变部分组合/洗牌的观感，需要试玩确认是否接受。
- 箱子挡住的下方格不会补子（规则如此）：verify_03/04/06 和 e2e 演示关里，箱子正下方的格在箱子打开前保持为空，校验会给出 C 类 `cut_off` 警告。这是规格行为，但对玩家可能显得“空洞”，需要关卡设计上注意。
- 编辑器缺口：多格选择与复制粘贴、镜像绘制、关卡列表手动排序、目录发布按钮（目前是“导出文件 → 放入 levels/src → node tools/make_levels.js”）、试玩中“暂停并按逻辑阶段推进”、正常显示尺寸预览面板 —— 均未做。编辑器为桌面优先，未适配手机。
- 编辑器测试多数通过脚本钩子 + 真实鼠标拖动完成；没有逐个人工点击每个控件。
- 玩家侧没有选关界面（阶段 C）；功能验证关通过 `?level=` 或开发面板进入。
- 不支持精确续局（规格 V1 可不做）。
- 性能：4× CPU 降速（固定 high 档）与 v2.2 对比无明显回退，障碍关在受击动画期间棋盘层逐帧重绘略增帧时间（见第 5 节数字）；均为无头数据。
