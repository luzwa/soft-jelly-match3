## 3. 修改内容与设计理由

### 3.1 规则核心 `js/rules_core.js`（CORE_VERSION 3.1.0-stageB，规则集仍为 jelly_rules_v1）
- **绑带**存于独立覆盖层 `st.over[k] = {id, kind:'tie'}`。被绑宿主不能交换、不能被交换道具移动、不下落（在重力分段里像箱子一样把列切开）、不被洗牌移动；可原地参与匹配。
  理由：§3 分层 + §4.1“绑带不吸收伤害”——绑带只是让宿主固定，不改变攻击传播。
- **解绑条件**：宿主格出现在本波匹配格中（来源 `host_matched`）或被直接攻击（`direct_attack`，含锤子、划线、炸弹、同色、组合）。邻格普通三消**不**解绑（§17.6）。宿主在解绑同一波按正常规则结算（被消除/收集/伤害地垫），不需要第二次命中。
- 绑带在本波“移除/生成”之前提交：锚点落在被绑格时，先解绑，再在已解绑的格上生成特殊（§17.8）。
- 绑带 ID 在占位物之后分配，因此阶段 A 关卡的 ID 序列与哈希完全不变。
- **果篮**是占位层对象：不可匹配、不可交换、对直接攻击免疫、受正常重力影响；出口来自关卡 `board.exits`。
- **结算顺序**：`settle()` = 下落 → 送达 → 下落 → 送达 …（上限 64 轮）直到稳定，再扫描下一波匹配（§6.1、§17.25）。每个送达事件 `{t:'deliver'}` 只发一次、目标 +1、得分 +100。
- 锤子敲“只有果篮、底下没有糖霜”的格 → 拒绝（`immune`），不扣道具（§17.25 后半）。果篮压在糖霜上时锤子只削糖霜。
- 全盘攻击、锤子都不能把果篮“计为送达”（§17.10）；只有落到出口格才计数。
- 彩虹 + 划线/炸弹没有可转换的同色普通果冻 → 拒绝、不扣步（原先会空放一次组合并扣步，玩家无法理解）。
- 同波去重显示修正：锤子直接命中绑带时去重计数不再出现 −1（只影响事件文本，不影响规则）。
- 显示用 `view()` 增加 `BSK`（果篮）、`^`（绑带）、`!`（出口）。

### 3.2 校验 `js/level_schema.js`
- A（结构错误）：出口越界/在空洞/重复/不在竖直连续段最下方（`exit_not_bottom`）；绑带压在箱子或果篮上（`tie_host`）；覆盖层未知类型或重复；果篮开局就在出口格（`basket_on_exit`）；果篮带特殊；送达目标但没有出口（`deliver_no_exit`）；目标字段错误。
- B（禁止发布）：果篮所在段没有出口（`basket_no_exit`，§6.1 同列同段路径）；送达目标数 > 果篮数（`deliver_short`）；有送达目标但没果篮（`no_baskets`）；清绑带目标但没有/不够绑带（`no_ties`/`tie_short`）。
- C（警告）：出口没有果篮使用（`exit_unused`）；`cut_off` 现在也把绑带算作阻挡。
- 规范化导出时出口排序，保证字节稳定。

### 3.3 游戏表现 `js/game.js`、`index.html`
- 新增画布 `#cOver`（在果冻层与棋盘层之间），只画绑带与果篮，按签名变化才重绘，跟随棋盘同一套几何与震屏变换 → 不影响 WebGL 批处理与分档。
- 出口画在静态棋盘层（下箭头），被缓存。
- 回放 `deliver` 事件：果篮滑入出口淡出 + 火花 + “送达!”飘字 + 目标更新；随后的独立 `fall` 事件正常播放。
- 绑带解除粒子；被绑果冻被拖动时“拽一下”并提示；`no_target`/`immune` 被拒有提示，不扣任何东西。
- 洗牌预览画出绑带和果篮；`visualCheck` 覆盖绑带与果篮（表现与核心逐格比对）。
- 软体果冻、画质档位、果冻美术未改。

### 3.4 编辑器 `editor.html`、`js/editor.js`
- 出口画笔：只能放在竖直连续段最下方的可用格，不能放在果篮格；擦除/挖空洞会同时移除出口。
- 绑带画笔：拒绝放在箱子或果篮上；果篮画笔：拒绝放在绑带或出口格上；箱子画笔拒绝放在绑带格上。拒绝时当场提示原因、不入撤销栈。
- 属性面板说明每层规则；目标面板可选“送达（全部/数量）”和清障碍类型（饼干箱/绑带）。
- 一次拖动 = 一步撤销，同阶段 A。

## 4. 完成的功能（对照 §16 阶段 B 与 §17）
