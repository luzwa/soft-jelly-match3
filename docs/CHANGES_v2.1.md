## 二、参数含义（所有新参数均为 **待测初值**）

### 时间步与休眠（`softbody.js`）

| 参数 | 值 | 含义 |
|---|---|---|
| `SIM_H` | 1/120 s | 固定模拟步长 |
| `MAX_LAG`（`SimClock.maxLag`） | 0.1 s | 累加器上限。长卡顿或切回前台时最多补 12 步，不会快进（待测初值） |

## 三、A/B 切换与回退

- **默认**：A，即 V2 显示。普通界面没有任何新按钮。
- **切到 B**，任选一种：
  - URL 加 `?octo=B`，例如 `index.html?octo=B`，file:// 下同样可用。
  - URL 加 `?dev=1` 打开开发面板（左下角），点“B 体积壳(候选)”。
  - 任何时候按 **Shift+D** 呼出或隐藏开发面板。
  - 测试中用 `JellyDebug.setOctoMode('B')`。
- **运行时回退**：面板点“A 当前”，或 `setOctoMode('A')`，立即生效，不需要重载。
- **自动回退到 A**：Canvas2D 兜底、光照程序初始化失败或没有深度缓冲时，B 不可用，自动按 A 绘制。特殊八爪鱼（条纹、炸弹）始终用 A，以保留 V2 的特殊着色。
- **完整回退**：直接使用 `releases/v2.0.0`。
- **只回退 B**：把 index.html 里的两个新 script 标签删掉即可，`p.vol` 不会再创建。时间步修复仍保留在 softbody.js 和 game.js 中。

## 四、验证结果（如实）

- **帧率确定性**：`test/timestep_v2.1.js`，Node 中用同一脚本运行。
  - 冲量测试，30/60/90/120/144 fps，含 ±40% 抖动：v2.1 振荡周期 315–348 ms，30 fps 有采样量化误差；稳定时间 1996–2017 ms；模拟时间÷真实时间 = 1.00。
  - v2.0.0 在 90 fps 时周期 422 ms、稳定 2467 ms、模拟只有真实时间的 0.75；144 fps 时周期 264 ms、稳定 1681 ms、模拟为 1.20 倍。
  - 落地脚本测试中，峰值形变受“落地事件落在哪一帧”影响：均匀帧率下 17.0–18.3 px；抖动帧率下 14.3–18.8 px，v2.0.0 为 16.7–18.6 px。这是事件按帧量化造成的，不是刚度差异，列为剩余问题。
- **V2 QA**（`qa_v21.js`）：
  - http 下 19/19 PASS；http 加 `?octo=B` 下 19/19 PASS；`?renderer=2d` 下 19/19 PASS。
  - file:// 启动无报错，A 和 B 都通过；B 在 file:// 下确认光照程序可用（webgl2，litDraws=9）。
  - 截图在 `shots_v2.1/qa*/`。
- **切换与卡顿检查**（`toggle_v21.js`）：7/7 PASS。内容：默认 A 无面板；Shift+D 开关面板；面板切到 B 再回 A；2D 兜底；主线程卡顿 1.5 s 后只补 12 步。
- **A/B 对照图**：`shots_v2.1/octo_ab_*.png` 和 `octo_ab_sheet.png`。两边同种子、同视口、同输入脚本，并用手动时钟保证帧完全相同。正常尺寸为 DPR 1；3× 特写是 DPR 3 真实渲染，不是放大。
- **演示视频**：`shots_v2.1/octo_b_demo.mp4`，4.4 s，30 fps。内容依次为交换、消除、补位落地、点按。用手动时钟逐帧渲染，每帧对应 33.3 ms 游戏时间，因此按正常速度播放。
- **性能**：`shots_v2.1/perf_v2.1.md`。本机为 SwiftShader 软件渲染，无 GPU，数值不具代表性。

**以上全部是静态截图、离线渲染和自动化测试，不代表“真实三维效果”或“手感”已经验收。** B 还没有在真机上手动操作过，也没有经过美术评审。

## 五、B 实际是什么

**B 是“二维模拟驱动的轻量三维外壳”**，满足简报优先方案的基本形态：

- 顶点有真实 z，有前后两层面。
- 厚度来自轮廓膨胀加手工头部椭球，不来自 PNG 亮度。
- 每帧在形变后重算法线。
- 用一盏固定灯光着色，有深度测试。
- 按压时局部压平，高光分布随之改变，而不是把原图亮斑拉伸。

它**不是**建模得到的三维角色，限制如下：

1. **侧转**：只支持约 ±10° 小幅侧转。侧面没有独立贴图，看到的是正面贴图边缘的拉伸，大角度会露馅。
2. **背面**：背面就是同一张正面贴图镜像过去的厚度层，只在侧转时露出很窄一条，没有真实背面美术。
3. **自遮挡**：头部与触手、触手与触手之间的厚度是同一张高度场，无法表达“触手从头后绕过”这种重叠。深度测试只能处理单层高度场的前后关系。
4. **厚度形状**：触手管径由二维轮廓推算，头部是手工椭球，与原画的真实体积只是近似。
5. **底色**：去光底色是算法近似，亮斑插值填补后，局部纹理略糊。

综合以上限制，**B 应视为“三维外壳 / 2.5D 候选”**：比纯法线增强多了真实厚度和深度，但达不到完整三维模型。

## 六、缺失资产（如实）

素材包没有以下资产，第一阶段全部用推算的占位：

- 去光底色（albedo）：算法生成。
- 粗糙度图：没有，着色器里用常量。
- 厚度/高度：轮廓膨胀加手工椭球。
- AO：由厚度场的凹陷和头部交界推算。
- 区域遮罩：脸部用手工椭圆；头部与触手由椭球推算。
- 透射和次表面参数：常量。
- 法线图：没有，法线由形变网格实时计算。
- 背面和侧面美术：没有。

如需更好的 B，应向美术索取：去光底色、厚度或高度图，或者低模；分区遮罩（头、腕足、眼、口）；粗糙度。

## 七、剩余问题

1. **V2 的重复压扁未改**：落地仍是关键帧加冲量，按压仍是压扁加指压加冲量（见 AUDIT 第 5 节）。按简报“第一轮保持弹性和时长”保留，B 只在最终结果上统一映射一次。是否收敛为单一来源，留到第七节调参时一并处理。
2. **按住时形变很大**：按住（hold）时的指压凹陷（0.23·S）与 V2 相同，B 的压平因此会触到限幅 zMin 0.6。是否需要减弱待真机试手感。
3. **落地峰值受帧量化影响**：峰值形变随落地事件所在的帧变化（±13%）。要彻底解决，需要把冲量放在对应的子步时间点施加，尚未做。
4. **B 的光栅化开销**：本机软件渲染下帧间隔约 +12 ms，需要真机 GPU 测量。可以降 `NG`、只画正面，或让远处和小尺寸的八爪鱼退回 A。
5. **B 的颜色**：整体亮度已与 A 对齐（A/B 平均亮度 0.492 vs 0.496）。但头部高光比原画小、更集中，触手光泽比原画弱，需要美术评审。
6. **退场对象**：退场的八爪鱼仍走 B 和完整模拟，“退场对象简化运动”尚未做。
7. **休眠阈值**：基于静态测试设定，可能让非常轻微的余震提前停住，0.12 px 以下不可见，但需要真机确认。
8. **VERSIONS.md 未更新**：按“不修改 releases/”的要求，`releases/VERSIONS.md` 没有更新，只新增了 zip。建议由你确认后补一行：v2.1.0-octoAB（第一阶段候选）。
