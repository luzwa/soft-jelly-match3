# v2.1 第一阶段 · 代码审查（对应简报第二节）

审查对象：`releases/v2.0.0`（= `game_v2/`，v2.1 从它复制而来）。下文行号指 v2.0.0 的源码；v2.1 改动见 `CHANGES_v2.1.md`。
审查时间：2026-10-10（UTC+8）。

## 1. 渲染方式与后端

- **后端**：WebGL2，取不到时退到 WebGL1；初始化失败或带 `?renderer=2d` 时用 Canvas2D 兜底。见 `js/renderer.js` 的 `Renderer()`（第 31–40 行）和 `initGL()`（第 41–65 行）。
- **三层画布**（`index.html`，`game.js` 的 `renderA / renderGL / renderB`，第 1501–1573 行）：
  - `cA`：Canvas2D，画背景、棋盘、HUD、道具栏。
  - `cG`：WebGL，只画果冻、阴影和光晕。
  - `cB`：Canvas2D，画粒子、横幅、面板，同时接收输入。
- **WebGL 着色**：
  - 只有一个 program（`VS/FS`，第 9–29 行）。
  - 2048×1024 图集，每个角色占一个 512 的格位（`SLOT`）。
  - 预乘 alpha；同一 batch 合批后一次 drawElements，按 scissor 裁剪。
  - 片元着色器只做贴图采样、特殊棋子的程序化图案（kind 1–4）、闪白，以及阴影/光晕/环（kind 10/11/12）。
  - **没有光照、法线和深度**：`initGL` 里 `gl.disable(gl.DEPTH_TEST)`。
- **Canvas2D 兜底**：`end2D()` 和 `tri()` 把网格拆成三角形，每个三角形做一次仿射贴图。

## 2. 整张 PNG / 二维网格 / 曲面 / 三维网格？

**结论：整张 PNG 贴在一张二维网格上，网格是 6×6 顶点、5×5 格，平面，没有 z。**

- 网格在 `softbody.js` 的 `Body()` 里生成（第 30–50 行）：
  - UV 覆盖精灵可见范围外扩 10px（`VB` 表）。
  - 静止形状 `qx=(u-0.5)·S, qy=(v-0.9)·S`，锚点在 v=0.9，八爪鱼可见底边约 461/512。
- **模拟网格和显示网格是同一套**：`R.mesh(body…)` 直接用 `body.px/py`（renderer.js 第 101–110 行）。
- 不是曲面，也不是三维网格；顶点没有深度和法线。

## 3. 颜色图是否烘焙了高光和阴影？（八爪鱼像素分析）

分析对象：`assets/characters/jelly_octopus/jelly_octopus_512.png`。脚本见 `tools/make_octopus_material.py`，结果存在 `assets/material/octopus_material_stats.json`。

**结论：有，而且很明显。**

- **镜面高光**：
  - 不透明像素 100,604 个。
  - 亮度 L 的中位数 0.47，p99 为 0.92，p99.9 为 0.997。
  - 严格判据（L>0.8 且饱和度<0.45）下的近白点占 1.8%：头部左上有一块大亮斑，触手上有连续的高光条。
  - 用局部亮度超出量（L − 6px 模糊 L > 0.05，且 L>0.6、sat<0.6）检测并外扩 2px 后，掩膜覆盖 13.3%。外扩部分主要是头部和触手轮廓上的边缘高光（rim）。
  - 掩膜见 `assets/material/octopus_specmask.png`。眼睛的反光点已排除，属于五官美术，保留。
- **漫反射明暗**：
  - 头部左半平均亮度 0.501，右半 0.428，与左上方光源一致。
  - 低频明暗（30px 加权模糊）在不透明区的 p5–p95 为 0.397–0.546。
  - 按行统计，头顶 y≈80–110 约 0.55–0.57，头部下缘 y≈260 约 0.42，触手底部 y≈440 又回到 0.60（底部反光）。
- **影响**：直接在这张图上再打一次光，会出现双高光，明暗方向也会叠两层。所以 B 用“去光”底色，见 CHANGES。去光只是近似：亮斑被遮掉后插值填补，低频明暗除掉约 55%。原稿没有分层源文件，做不到精确还原。

## 5. 物理网格 / 父节点缩放 / 着色器是否重复压扁

- **物理网格**：有，就是上面的 6×6 软体。
- **父节点缩放**：没有场景树。但 `poseOf` 把多路缩放相乘后作为软体目标（只施加一次），同时又有冲量直接打在软体上。**同一个事件因此会被脚本和模拟各压一次**：
  - **落地**：`dropColumn` 同时调用 `landSquash(p,k)`（关键帧压扁）和 `p.body.land(str)`（冲量压扁），第 376–377 行。
  - **按压**：`press()` 里的 `squashTo(1.025·1.03, 0.96·0.97)`、`fingerOn()` 的指压凹陷 `fdepT=0.23·S`、`body.kick(0,120,'top')` 三者叠加。
  - **消除**：`popPiece()` 直接设 `sqW=1.22, sqH=0.8`，同时 `body.radial(520)`。
  - **下落**：`vyc` 速度拉伸和 `landSquash` 首帧可能前后衔接。
  - **退场**：`stepFly` 覆盖写 `sqW/sqH`。
- **着色器**：不做几何压扁，只着色，所以没有第三次。阴影的 `sqW` 另算宽度，不影响本体。
- **处理（第一阶段）**：
  - 简报要求“第一轮保持弹性和时长”，所以 V2 的脚本加冲量组合原样保留，没有删减（见 CHANGES 剩余问题）。
  - B 的三维显示把这些形变的最终结果（`body.px/py`）只映射一次。深度项、按压压平、限幅在 `volume.js` 里合成为一个系数，限幅后只乘一次。
  - B 把横向加宽的 40% 改为转入厚度（`widenShare`），只在 `poseOf` 里改一次。

## 6. 时间步、阻尼、迭代是否随帧率改变软硬

**结论：会。**

- **v2.0.0 的步进**（`updatePiece`，第 929–940 行）：
  - 每帧做 `n = clamp(round(dt/H),1,5)` 个 H=1/120 s 的子步。
  - 90fps 时 dt=11.1ms，n=1，模拟时间只有真实时间的 0.75。
  - 144fps 时 dt=6.9ms，n=1，模拟时间是真实时间的 1.2。
  - 帧时间超过 50ms 被截断（`frame()` 第 1578 行），低于 20fps 时整体变慢。
- **阻尼**：`exp(-damp·h)` 本身是按时间定义的，但 h 与真实时间不对应，所以效果仍随帧率变化。
- **迭代**：每子步一次形状匹配，没有迭代求解器，迭代次数不随帧率变。
- **休眠**：没有，49 颗每帧都完整模拟。
- **后台恢复**：`visibilitychange` 时把 `lastRaw` 清零，首帧按 16ms 算，这一点是对的。
- **确定性测试**（`test/timestep_v2.1.js`，结果在 `test/timestep_v2.1_result.json`）：冲量测试，静止姿态下顶部施加 `kick(0,300)`；“周期”指顶点第一、二个峰的间隔；“稳定”指 max|d| 降到 0.3px 以下。

| fps | v2.0.0 周期 / 稳定 / 模拟÷真实 | v2.1 周期 / 稳定 / 模拟÷真实 |
|---|---|---|
| 30 | 300 ms / 2033 ms / 1.00 | 333* ms / 2000 ms / 1.00 |
| 60 | 317 / 2017 / 1.00 | 317 / 2000 / 1.00 |
| 90 | **422 / 2467 / 0.75** | 322 / 2011 / 1.00 |
| 120 | 317 / 2017 / 1.00 | 317 / 2008 / 1.00 |
| 144 | **264 / 1681 / 1.20** | 319 / 2014 / 1.00 |

\* 30fps 下峰值只能在 33ms 的帧上采样，周期量化误差约 ±33ms。峰值幅度 v2.1 为 12.85–13.11px。

## 7. 可复用的原型几何、材质、形变代码

- **可复用**：
  - `softbody.js` 的形状匹配软体（v2.1 继续作为模拟层）。
  - `renderer.js` 的合批、scissor、图集、预乘 alpha 流程，以及 kind 1–4 特殊着色。
  - `core.js` 的 `Clock` 补间与 `landingAt` 关键帧。
  - `motion_rules.json` 已有 `depth` 轴数值。例如落地 t0.16 是 w1.035/h0.94/d1.03；按压是 w1.025/h0.96/d1.015。这些值恰好约等于 1/(w·h)，即体积守恒，但 v2.0.0 没用上。v2.1 的 B 用面积比推出厚度系数，与这组数一致。
  - `JellyDebug` 测试钩子。
- **不存在、无法复用**：
  - 简报提到的“原型几何/材质”源码不在工程和素材包里。
  - 素材包里只有 PNG（512/1024 加 generated_masters），没有三维模型、法线、粗糙度、厚度或分区遮罩。
  - `FX_AND_MOTION_RULES.md` 明确写着“PNG 无背面、体积、软体”。
- **最小改造路线**：
  - 不换引擎，模拟层（6×6）不动。
  - 只给八爪鱼加一条可切换的显示路径（B）。
  - 时间步修复对所有棋子生效，但不改任何弹性参数。
